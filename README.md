

# ☕ Dominando Java: De SE a EE

Este repositorio es una bitácora detallada de mi camino hacia el dominio del ecosistema Java. Aquí documento desde los fundamentos de **Java SE** hasta arquitecturas complejas en **Java EE (Jakarta EE)**.

## 📌 Mapa de Ruta (Roadmap)

### 1. Java Standard Edition (Java SE) - [EN PROCESO]

Es la base de todo. Aquí me enfoco en el núcleo del lenguaje.

* **Fundamentos:** Tipos de datos, operadores lógicos (and, or, not, entonces).
* **Estructuras de Control:** Uso profesional de `do-while`, `for`, `if-else`.
* **POO (Los 4 Pilares):**
* *Encapsulamiento y Herencia:* Estructura y protección de datos.
* *Abstracción y Polimorfismo:* Contratos mediante clases abstractas y flexibilidad de comportamiento.


* **Colecciones y Excepciones:** Gestión de datos y robustez del código.

### 2. Java Enterprise Edition (Jakarta EE) - [PRÓXIMAMENTE]

Enfoque en aplicaciones empresariales y servidores.

* Servlets y JSP.
* Persistencia con JPA / Hibernate.
* Web Services (REST & SOAP).

### 3. Java Micro Edition (Java ME) - [CONCEPTUAL]

Estudio de entornos limitados y sistemas embebidos.

---

## 🛠️ Tecnologías y Herramientas

* **Lenguaje:** Java 17+ (o la versión que estés usando).
* **IDE:** IntelliJ IDEA / Eclipse.
* **Control de Versiones:** Git & GitHub.
* **Gestor de Dependencias:** Maven / Gradle.

---

## 📂 Estructura del Proyecto

Organizo los paquetes por conceptos para mantener una **Alta Cohesión**:

* `src/com.yordan.fundamentos`: Sintaxis básica.
* `src/com.yordan.poo.estructura`: Encapsulamiento y Herencia.
* `src/com.yordan.poo.comportamiento`: Abstracción y Polimorfismo.

---

## 🚀 Cómo usar este repositorio

Cada paquete contiene un archivo `notas.txt` o comentarios en el código que explican la teoría detrás de la implementación, ideal para repasos rápidos de exámenes o proyectos de la universidad.

### Consejos adicionales para tu MD:

1. **Usa Badges:** Puedes añadir iconos de Java o Git para que se vea más visual.
2. **Explica el "Por qué":** Como lo que hablamos de agrupar Abstracción y Polimorfismo. Si pones en tu MD: *"Agrupo estos dos porque la abstracción define el contrato que el polimorfismo ejecuta"*, cualquier reclutador que vea tu GitHub sabrá que entiendes la teoría a fondo.
3. **Progreso:** Usa Checkboxes (`- [x]` o `- [ ]`) para mostrar qué temas ya dominaste.

¿Te parece bien esta estructura o prefieres algo más minimalista enfocado solo en el código? Por cierto, ¡gran detalle incluir la lógica de "entonces" y "si solo si" en tus fundamentos! Eso te da un perfil más analítico.
